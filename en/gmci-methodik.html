1. Background and purpose

This tool calculates an approximation of the Green-Moist-Cool Index (GMCI) — in German, Grün-Feucht-Kühl-Index (GFKI) — for any German postal code. The GMCI was first described in:

Adhikari, Y., Ibisch, P. L., Wohlleben, P., Schneider, A., & Johnson, D. (2026). Working landscapes under climate change need to be green, moist, and cool—A case study of Germany. Ecological Solutions and Evidence, 7(2), e70270. doi.org/10.1002/2688-8319.70270

2. Underlying original methodology

According to the original publication (Section 2.5), the GMCI is defined as follows:

  1. Three input variables are determined per pixel and year: NDVIsep (September vegetation index), LSThot (maximum land surface temperature on hot days, ≥ 40 °C), and precipitation (annual total in mm).
  2. NDVIsep and precipitation are linearly scaled to 0–1 (higher values = positive).
  3. LSThot is also scaled to 0–1 and then inverted (cooler areas = higher values).
  4. The GMCI of a pixel is the simple arithmetic mean of the three scaled values.
  5. Multi-year composites are formed by averaging the annual GMCI values.

This formula is explicitly described in the original paper; not documented, however, are the exact min/max reference values used for the 0–1 scaling.

3. Data basis of this implementation

3.1 Raster data

This tool uses the publicly available raster datasets provided by the original authors:

Adhikari, Y., & Ibisch, P. (2025). Working landscapes under climate change need to be green, moist and cool—A case study of Germany [Data set]. Zenodo. doi.org/10.5281/zenodo.17081072
LayerSourceContentResolution
LST_YYYY.tifLandsat 8 & 9Surface temperature on hot days, only ≥ 40 °C~500 m
NDVI_YYYY.tifMODIS MOD13Q1September vegetation index~500 m
PPT_YYYY.tifGerman Weather ServiceAnnual precipitation total (mm)~500 m

Technical properties (independently verified): coordinate system EPSG:4326, nodata encoded as NaN. The three layers are not pixel-perfectly aligned, so each coordinate lookup is performed separately per layer.

3.2 Postal code coordinates

Postal code → coordinate mapping uses an open, OpenStreetMap-based dataset from postleitzahl.net (license: ODbL/CC-BY-SA) covering approx. 8,170 German postal codes with centroid coordinates.

4. Calculation steps

The full implementation is available as a Python script. The calculation runs in six steps:

Step 1 — Load base data

For each year (2018–2024), the three raster files are read and nationwide min/max values of valid pixels are determined.

Step 2 — Determine pixel value per coordinate (with fallback)

Since the LST and NDVI layers have substantial nodata gaps, a nearest-valid-pixel fallback is used when a value is missing: on NaN, a growing search radius (up to 20 pixels) looks for valid neighbours and uses their average. If the search is unsuccessful, that year is excluded from the average for that component.

Step 3 — Normalization (0–1 scaling)

scaled = (value − minimum) / (maximum − minimum)

For LST, the result is additionally inverted (1 − scaled), so cooler locations score higher.

Step 4 — Calculate annual GMCI

GMCI_year = (LST_scaled_inverted + NDVI_scaled + PPT_scaled) / 3

Step 5 — Form multi-year average

The final GMCI value per postal code is the arithmetic mean of the available annual GMCI values (2018–2024). The number of years included is displayed transparently.

Step 6 — Save results

{"01067": {"gmci": 0.377, "years": 7, "place": "Dresden"}, ...}

The web component performs a purely client-side lookup on postal code entry — no live calculation happens in the browser or on a server.

5. Classification into categories

The numeric GMCI value (0–1) is divided into five categories, based on the classification from the original authors' follow-up paper:

GMCI rangeCategory
≤ 0.30Very critical
≤ 0.40Critical
≤ 0.50Moderate
≤ 0.60Good
> 0.60Very good

These thresholds are our own, plausibly chosen boundaries, not officially adopted class boundaries.

6. Deviations from the official methodology

  1. Unknown reference normalization values: the actual nationwide extreme values of the raster data for the respective year are used as a substitute.
  2. NDVI data source: the original paper uses Sentinel-2 (10 m resolution); the public dataset is based on MODIS (~250 m), which can cause deviations.
  3. Fallback mechanism: the nearest-valid-pixel fallback is our own addition, not described in the original, but necessary for practically usable postal code lookups.
  4. Class boundaries: our own plausible interpretation (see Section 5).
  5. Time period: 2018–2024 (available dataset) instead of 2021–2025 (official 2026 publication).

Consequence: the displayed value may differ from a hypothetical official GFKI value for the same postal code. It should be understood as a plausible, methodologically traceable approximation, not an exact reproduction.

7. Validation / plausibility check

The following samples were used for plausibility checking during development:

  • Karlsruhe (76133): GMCI ≈ 0.42–0.45 — densely built urban area, expected moderate value
  • Feldberg/Black Forest (79868): GMCI ≈ 0.53–0.58 — natural landscape, expected higher than Karlsruhe
  • Berlin-Mitte (10117): GMCI ≈ 0.34 — heavily sealed inner-city location, expected low

The relative ranking of these test points matches expectations from the original study — an indication of basic plausibility, even without independent validation against official GFKI maps.

8. Reproducibility

The entire calculation is reproducible via the precompute_gmci.py script. Required: the 21 GeoTIFF files from Zenodo, the postal code coordinate table, and Python 3 with rasterio and numpy:

python3 precompute_gmci.py \
  --csv plz_einwohner.csv \
  --data-dir <folder with GeoTIFFs> \
  --years 2018 2019 2020 2021 2022 2023 2024 \
  --out gmci-daten.json
