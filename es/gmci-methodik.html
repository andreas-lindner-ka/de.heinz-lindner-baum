1. Contexto y objetivo

Esta herramienta calcula una aproximación al Índice Verde-Húmedo-Fresco (GMCI) — en alemán, Grün-Feucht-Kühl-Index (GFKI) — para cualquier código postal alemán. El GMCI fue descrito por primera vez en:

Adhikari, Y., Ibisch, P. L., Wohlleben, P., Schneider, A., & Johnson, D. (2026). Working landscapes under climate change need to be green, moist, and cool—A case study of Germany. Ecological Solutions and Evidence, 7(2), e70270. doi.org/10.1002/2688-8319.70270

2. Metodología original de referencia

Según la publicación original (sección 2.5), el GMCI se define de la siguiente manera:

  1. Se determinan tres variables de entrada por píxel y año: NDVIsep (índice de vegetación de septiembre), LSThot (temperatura máxima de la superficie terrestre en días calurosos, ≥ 40 °C) y precipitación (suma anual en mm).
  2. NDVIsep y la precipitación se escalan linealmente a 0–1 (valores más altos = positivo).
  3. LSThot también se escala a 0–1 y luego se invierte (zonas más frescas = valores más altos).
  4. El GMCI de un píxel es la media aritmética simple de los tres valores escalados.
  5. Los compuestos multianuales se forman promediando los valores anuales de GMCI.

Esta fórmula se describe explícitamente en el artículo original; sin embargo, no están documentados los valores de referencia mín/máx exactos utilizados para el escalado 0–1.

3. Base de datos de esta implementación

3.1 Datos ráster

Se utilizan los conjuntos de datos ráster de acceso público proporcionados por los autores originales:

Adhikari, Y., & Ibisch, P. (2025). Working landscapes under climate change need to be green, moist and cool—A case study of Germany [conjunto de datos]. Zenodo. doi.org/10.5281/zenodo.17081072
CapaFuenteContenidoResolución
LST_YYYY.tifLandsat 8 y 9Temperatura superficial en días calurosos, solo ≥ 40 °C~500 m
NDVI_YYYY.tifMODIS MOD13Q1Índice de vegetación de septiembre~500 m
PPT_YYYY.tifServicio Meteorológico AlemánSuma anual de precipitación (mm)~500 m

Propiedades técnicas (verificadas independientemente): sistema de coordenadas EPSG:4326, valores nulos codificados como NaN. Las tres capas no coinciden exactamente a nivel de píxel, por lo que cada consulta de coordenadas se realiza por separado para cada capa.

3.2 Coordenadas de códigos postales

La asignación de código postal a coordenadas utiliza un conjunto de datos abierto, basado en OpenStreetMap, de postleitzahl.net (licencia: ODbL/CC-BY-SA), que cubre aproximadamente 8.170 códigos postales alemanes con coordenadas de centroide.

4. Pasos del cálculo

La implementación completa está disponible como un script de Python. El cálculo se ejecuta en seis pasos:

Paso 1 — Cargar datos base

Para cada año (2018–2024), se leen los tres archivos ráster y se determinan los valores mín/máx a nivel nacional de los píxeles válidos.

Paso 2 — Determinar el valor de píxel por coordenada (con respaldo)

Dado que las capas LST y NDVI presentan importantes vacíos de datos, se utiliza un respaldo del píxel válido más cercano cuando falta un valor: ante un NaN, se busca en un radio de búsqueda creciente (hasta 20 píxeles) píxeles vecinos válidos y se utiliza su promedio. Si la búsqueda no tiene éxito, ese año se excluye del promedio para ese componente.

Paso 3 — Normalización (escalado 0–1)

escalado = (valor − mínimo) / (máximo − mínimo)

Para LST, el resultado se invierte adicionalmente (1 − escalado), de modo que las ubicaciones más frescas obtienen una puntuación más alta.

Paso 4 — Calcular el GMCI anual

GMCI_año = (LST_escalado_invertido + NDVI_escalado + PPT_escalado) / 3

Paso 5 — Formar el promedio multianual

El valor final de GMCI por código postal es la media aritmética de los valores anuales de GMCI disponibles (2018–2024). El número de años incluidos se muestra de forma transparente.

Paso 6 — Guardar resultados

{"01067": {"gmci": 0.377, "años": 7, "lugar": "Dresden"}, ...}

El componente web realiza una consulta puramente del lado del cliente al introducir el código postal — no se realiza ningún cálculo en tiempo real en el navegador ni en un servidor.

5. Clasificación en categorías

El valor numérico de GMCI (0–1) se divide en cinco categorías, basadas en la clasificación del artículo de seguimiento de los autores originales:

Rango de GMCICategoría
≤ 0,30Muy crítico
≤ 0,40Crítico
≤ 0,50Moderado
≤ 0,60Bueno
> 0,60Muy bueno

Estos umbrales son límites propios, elegidos de forma plausible, y no límites de clase adoptados oficialmente.

6. Desviaciones respecto a la metodología oficial

  1. Valores de normalización de referencia desconocidos: como sustituto, se utilizan los valores extremos reales a nivel nacional de los datos ráster del año correspondiente.
  2. Fuente de datos NDVI: el artículo original utiliza Sentinel-2 (resolución de 10 m); el conjunto de datos público se basa en MODIS (~250 m), lo que puede causar desviaciones.
  3. Mecanismo de respaldo: el respaldo del píxel válido más cercano es una adición propia, no descrita en el original, pero necesaria para consultas de códigos postales prácticamente utilizables.
  4. Límites de clase: interpretación propia y plausible (véase la sección 5).
  5. Período de tiempo: 2018–2024 (conjunto de datos disponible) en lugar de 2021–2025 (publicación oficial de 2026).

Consecuencia: el valor mostrado puede diferir de un hipotético valor oficial de GFKI para el mismo código postal. Debe entenderse como una aproximación plausible y metodológicamente trazable, no como una reproducción exacta.

7. Validación / comprobación de plausibilidad

Durante el desarrollo se utilizaron las siguientes muestras para la comprobación de plausibilidad:

  • Karlsruhe (76133): GMCI ≈ 0,42–0,45 — zona urbana densamente edificada, valor moderado esperado
  • Feldberg/Selva Negra (79868): GMCI ≈ 0,53–0,58 — paisaje natural, valor esperado más alto que Karlsruhe
  • Berlín-Mitte (10117): GMCI ≈ 0,34 — zona céntrica fuertemente sellada, valor bajo esperado

La clasificación relativa de estos puntos de prueba coincide con las expectativas del estudio original — un indicio de plausibilidad básica, aunque sin validación independiente frente a mapas oficiales de GFKI.

8. Reproducibilidad

Todo el cálculo es reproducible mediante el script precompute_gmci.py. Se necesitan los 21 archivos GeoTIFF de Zenodo, la tabla de coordenadas de códigos postales y Python 3 con rasterio y numpy:

python3 precompute_gmci.py \
  --csv plz_einwohner.csv \
  --data-dir <carpeta con GeoTIFFs> \
  --years 2018 2019 2020 2021 2022 2023 2024 \
  --out gmci-daten.json
